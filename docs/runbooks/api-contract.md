# API contract and telemetry

The authoritative Nest API publishes `GET /api/v1/openapi.json`; the same-origin Next gateway exposes the same route. `node --import tsx scripts/export-openapi.ts` regenerates `docs/api/openapi.json` from the Zod request schemas used by dispatch. The document records current paths, body constraints, credential families, mutation origin/CSRF headers, idempotency keys, binary formats and stable errors. Domain role/publication/capacity/approval invariants remain runtime checks, not JSON Schema claims. Client generators must preserve cookie isolation and the configured public origin.

API responses carry a generated UUID `X-Request-Id` (or a validated incoming UUID). The gateway forwards it. Structured completion logs contain request ID, method, route family, status, milliseconds and, where applicable, pseudonymous tenant and UUID operation IDs. They omit URLs, query strings, cookies, bodies, names, answers, provider images and credentials. Malformed JSON returns `INVALID_JSON`; oversized JSON returns `BODY_TOO_LARGE`. Keep business audit records separate from these operational logs. Ship JSON logs to the deployment's configured collector; do not turn raw HTTP/body debug logging on for guest traffic.

Media lists return up to 200 authorised rows plus `nextCursor`. Pass the opaque cursor to `GET /api/v1/weddings/{weddingId}/media?cursor=...`; it binds list kind and wedding and preserves position, microsecond timestamp and UUID ordering. Every page rechecks current tenant/album access. Invalid/cross-list cursors return `INVALID_CURSOR` and advise first-page reload. Cursors are not credentials or snapshot locks: concurrent reorders may change a later page; return to the first page to review current content. Media UI has first/previous/next controls and loading/retry states.

Invitation exports and creative run history now return 100 rows plus a scoped `nextCursor`, passed to their existing list endpoint. The UI can load older history while preserving drafts; polling retains the loaded history extent. Photo selection can load later media pages. Remaining protocol work is tracked in implementation-status: other growing lists need cursor navigation, and the remaining growing lists need cursor navigation. Do not describe the current document as proof that those remaining behaviours are implemented.

Authenticated asynchronous invitation/brief/AI/archive/email-retry responses now return actual `jobId` and `jobIds` alongside the domain `id`; initial enqueue responses include a protected `statusPath`. JPEG/PDF jobs are separate: one completed job does not mean the whole bundle is complete. Timeout replay keeps the original enqueue job IDs, even after later format retries. Each format retry returns its own new job ID. `GET /api/v1/weddings/{weddingId}/jobs/{jobId}` exposes state/attempts/safe error/times only; it rechecks membership and applicable requester/album scope, and excludes payloads/provider references/lease tokens. Guest upload acknowledgements include their processing job ID but retain upload-session status polling; job-status access remains staff-scoped. Anonymous identity acknowledgements stay generic to avoid account enumeration and grant no job access.

Workspace discovery GET /weddings returns `{weddings,nextCursor}` with up to50 rows; pass cursor on the same route. It binds the signed-in account and rechecks current membership and deletion on every page. This replaces the previous bare-array response; the connected web client and generated OpenAPI use the current contract.

GET /weddings/{weddingId}/members returns up to100 members and100 invitations, with separate nextMemberCursor/nextInviteCursor. Send memberCursor/inviteCursor independently; cursors bind list kind and wedding. Each request rechecks current owner/co-owner capability. Invitation DTOs exclude token hashes. Refresh after access changes returns the first pages so removed access is not retained.
