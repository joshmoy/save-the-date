# ADR 018 — Encrypted recovery and independent admission state

Accepted 2026-10-13. Implements TRD recovery and PRD M05/O02/P03 without changing the legacy wedding database or existing secrets.

Backups use PostgreSQL 16 custom dumps from a repeatable-read exported snapshot. All platform table fingerprints, required completed object references, private object bytes/types/SHA-256 and licensed font assets form a bounded TAR inventory. AES-256-GCM authenticates the complete bundle before extraction. A checked encrypted replica and explicit thirty-day expiry are required. Storage and encryption remain interfaces; the supported CLI destinations are filesystem volumes, which production must place in independent failure domains. Local directories alone do not demonstrate hardware resilience.

Acknowledging admission requires an independently durable private journal. Write intent while holding the event/pass database locks, commit the single admission, then write committed acknowledgement. A failure before database commit consumes no pass; a failure after commit returns uncertainty and the same operation key repairs the acknowledgement. Recovery replays committed admissions from outside the old database snapshot. Uncertain intents pause scanning; verified allowlisted operators require recent authentication, independent no-admission confirmation and an audited reason to resolve them. Missing lineage cannot be dismissed through that control. The journal contains UUIDs/times, no names, contact details or admission credentials. Production requires failure-independent durable ledger storage and fencing of the old writer.

Individual media, guest, post and membership removals also have independent erasure markers. Replay removes affected server invitation, planner brief and archive copies; downloaded immutable files remain outside server control. Fully erased accounts/workspaces carry terminal markers. Startup replays independent recovery state before accepting traffic.

The supported restore path revokes prior passwords/sessions/grants, holds website publication, resets restored media approval and disables uncertain external email/AI jobs. Owners recover passwords, review media and explicitly republish. This conservative boundary prevents an older snapshot silently restoring revoked access or paid submissions. The isolated rehearsal proves invariants on synthetic data, not production RPO/RTO. Production must supply scheduled/continuous recovery, independent object/ledger replication, secrets/config/image recovery and regular timed restore drills before advertising the specified recovery tier.
